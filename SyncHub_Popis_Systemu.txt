1. PREHĽAD SYSTÉMU
==================

SyncHub je modulárna integračná platforma vyvinutá na mieru pre spoločnosť
SEDAJ s.r.o. / Hauerland. Hlavným účelom systému je prepojenie interného ERP
systému ONIX (KROS a.s.) s 13 externými systémami dodávateľov, e-shopov a CRM
nástrojov pomocou REST API, XML feedov a JSON feedov.

Platforma zabezpečuje automatizovanú, spoľahlivú a auditovateľnú výmenu dát
medzi systémami bez manuálnych zásahov. Každý synchronizačný cyklus je
zaznamenávaný s podrobným logom, štatistikami a históriou zmien.

Systém beží ako webová aplikácia dostupná z prehliadača, s bezpečným
prihlasovaním, riadením rolí a kompletným auditom všetkých operácií.

5. SYNCHRONIZAČNÝ ENGINE (4-FÁZOVÝ PIPELINE)
=============================================

Jadrom systému je vlastný synchronizačný engine implementovaný v TypeScript
(server/sync-engine.ts, server/target-push.ts, server/data-fetcher.ts).

5.1 Fáza 1 — Preflight (predbežná kontrola)
---------------------------------------------
- Validácia konfigurácie synchronizácie
- Overenie dostupnosti zdrojového a cieľového modulu
- Kontrola oprávnení a API kľúčov
- Overenie mapovania polí

5.2 Fáza 2 — Backup (zálohovanie)
-----------------------------------
- Voliteľné zálohovanie cieľových dát pred synchronizáciou
- Export existujúcich záznamov z ONIX do JSON
- Uloženie zálohy na Google Drive (cez Replit Connectors)
- Zaznamenanie metadát zálohy do databázy (fileId, fileSize, recordCount)
- Možnosť obnovy zálohy (restore) cez UI

5.3 Fáza 3 — Fetch (načítanie dát)
------------------------------------
- Načítanie zdrojových dát zo zdroja (REST API / XML feed / JSON feed)
- Retry logika pri zlyhaní sieťového požiadavku (3 pokusy + backoff)
- SSRF ochrana — allowlist povolených hostiteľov
- Streamované spracovanie pre veľké XML feedy (pamäťovo efektívne)
- Delta Diff — porovnanie MD5 hashov namapovaných polí s uloženou základňou
  (sync_baselines), vynechanie nezmenených záznamov
- Meranie rýchlosti načítania a odhadovaného času dokončenia

5.4 Fáza 4 — Sync (synchronizácia)
-------------------------------------
- Dávkové spracovanie (50 záznamov / batch)
- Transformácie dát podľa mapovacej konfigurácie:
    * Priame mapovanie poľa na pole
    * Cenové výpočty (násobenie, delenie)
    * Odstránenie DPH
    * Zmena veľkosti písmen (uppercase, lowercase, capitalize)
    * Vlastné JavaScript výrazy
- Matching záznamov v cieli podľa konfigurovateľných polí (matchFields)
- Stratégie pri nenájdenom zázname: vytvoriť / preskočiť / chyba
- Sekvenčné volanie ONIX API (jeden záznam za druhým — požiadavka KROS)
- Retry mechanizmus pri HTTP chybách (429, 500, 503)
- Konfigurovateľná konkurencia pre non-ONIX systémy
- Live progress update cez polling (stav každých ~1s)
- Early stop podmienky (príliš veľa chýb za sebou)
- Zombie run cleanup pri reštarte servera
- Resilient DB write s exponenciálnym backoff (resilientDbUpdate)

5.5 Výsledné metriky každého runu
-----------------------------------
- Celkový počet spracovaných záznamov
- Počet vytvorených / aktualizovaných / preskočených / chybných záznamov
- Rýchlosť spracovania (záznamy/minútu)
- Čas začiatku a konca
- Číslo aktuálneho batchu a celkový počet batchov
- Detailný log každého záznamu (voliteľne)

8. BEZPEČNOSŤ
=============

8.1 Autentifikácia a autorizácia
----------------------------------
- Session-based autentifikácia (express-session + PostgreSQL session store)
- bcrypt hashovanie hesiel (cost factor 10)
- Tri roly s rôznymi oprávneniami:
    * Admin — plný prístup vrátane správy používateľov
    * Operator — správa modulov, synchronizácií, spúšťanie behov
    * Viewer — iba čítanie, monitorovanie
- requireAuth / requireRole middleware na každom endpointe

8.2 SSRF ochrana
-----------------
- Allowlist povolených externých hostiteľov pre sieťové požiadavky
- Zamedzenie volania interných/lokálnych IP adries

8.3 Bezpečné úložisko kľúčov
------------------------------
- API kľúče a tokeny dodávateľov uložené v Replit Secrets (šifrované)
- Produkčné ONIX tokeny uložené oddelene od testovacích
- Vault stránka pre správu a overenie dostupnosti kľúčov

8.4 Audit logging
------------------
- Každá kritická akcia je zaznamenaná s IP adresou, časom a ID používateľa
- Logované akcie: prihlásenie/odhlásenie, zmena konfigurácie, spustenie syncu,
  zmena používateľov, prístup k Vault, zálohy a obnovy

10. ŠPECIÁLNE FUNKCIE A VÝKONNOSTNÉ OPTIMALIZÁCIE
===================================================

10.1 Delta synchronizácia (Incremental sync)
---------------------------------------------
- MD5 hashovanie hodnôt namapovaných polí každého záznamu
- Porovnanie s uloženou základňou (sync_baselines tabuľka)
- Ak sa hash nezmenil → záznam sa preskočí (žiadne API volanie)
- Dramatické zníženie počtu API volaní pri opakovaných bežiach
- Voliteľný "Full sync" tlačidlom (ignoruje baseline)

10.2 H-číslovanie (automatické kódovanie pre ONIX)
----------------------------------------------------
- Konfigurovateľný prefix (napr. "H20")
- Automatické prideľovanie sekvenčného čísla každému novému záznamu
- Perzistentné ukladanie posledného použitého čísla (per konfigurácia)
- Zabezpečuje jedinečnosť Ns_Number v ONIX

10.3 Dávkové spracovanie
-------------------------
- Záznamy spracovávané po 50-kusových dávkach (batches)
- Zamedzenie timeoutov pri veľkých datasetoch
- Progress reporting po každom batchi

10.4 Retry mechanizmus
-----------------------
- Automatický retry pri HTTP 429 (rate limit), 500, 503
- Exponenciálny backoff (1s → 2s → 4s)
- Maximálne 3 pokusy na záznam / API volanie

10.5 Resilient DB zápis
------------------------
- Kritické databázové zápisy (update stavu behu) s retry logikou
- Zamedzenie straty metadát pri krátkodobom výpadku DB

10.6 Zombie run cleanup
------------------------
- Pri štarte servera automaticky ukončí visiaće ("zombie") synchronizáčné behy
- Zamedzenie nekonzistentného stavu po reštarte

10.7 CSV export
----------------
- Export dát ľubovoľného modulu do CSV súboru priamo z UI
- Užitočné pre ad-hoc analýzy a overovanie dát
